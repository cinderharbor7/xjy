## 一、项目介绍（对应 5.2 第 1 项）

- **队名 / 成员**：【TBD：队长填写】
- **项目名称**：Risk Guardian —— 可复查的 Ethereum 异动调查原型（附受限保护执行实验）
- **目标用户（假设，未验证）**：承担 ETH 异动核验、需要把判断交给他人复查的投研 / 运营人员。
- **解决的问题**：社媒/群聊出现带交易哈希的 ETH 大额异动消息时，核验者需要分清"确认事实、证据支持的解释、证据缺口"，交出别人能复查的判断。公开误读案例（Cointelegraph 对 Kanro 多签转账的更正）证明这类核验工作真实发生。
- **核心功能**（均已在仓库验收，性质分别标注）：
  1. **量化观察与规则分析**（真实主网只读）：相邻 5 分钟窗口单池 gross sell-pressure 对比，确定性 Risk/Confidence 输出，逐条引用与固定未知项。
  2. **具体交易证据核验**（真实主网只读）：输入 txHash，输出外层交易事实、固定池 Swap 方向与精确数量、中文解释与未知项；入口 `/investigate`。
  3. **受限保护执行实验**（独立 Mock 演示，Fork 本轮未运行）：用户预设六条硬规则批准 → 单向减仓 → 独立重读 → 八项效果验证；一次事件最多一笔 swap，重复请求 409 拒绝。
- **比赛期间完成的工作**：上述异动调查（量化观察＋交易核验）、受限保护实验与报告存证为本次比赛新增；统一原生前端与货币指纹设计体系为既有基础（沿用来源见下节）。【TBD：队长按实际参赛历史最终确认新增/沿用划分】
- **如实披露**：当前没有真实 AI/Agent 参与调查（规则生成解释，为公开缺口）；使用者/采用/付费均为假设；AI 对照实测（AC-006）尚未完成，不声明相对通用 AI 的优势；不做主网自动交易、价格预测、身份鉴定。

- **真实主网只读查询**（可选）：在 `.env.local` 配置 `ETHEREUM_RPC_URL`（主网 chain id=1，需支持历史区块、日志与 `blockHash + requireCanonical`）后：

```bash

# 或启动服务后使用页面 /investigate 与 POST /api/transaction-checks
```
