## 二、Policy 门控（实测，正例）

策略由 HTTP 写入，`version` 从 1 递增到 2。以下为配置摘要，不是完整请求；当前 `PUT /api/policy` 请求还需 `wallet`、`version` 和 `config` 包装：

```
PUT /api/policy
{"minRiskScore":80,"minConfidence":0.85,"minRiskExposurePct":70,
 "maxDeRiskPct":30,"allowedRiskAssets":["ETH"],"allowedDefensiveAssets":["USDC"]}
```

事件内保存的 `policyDecision` 显示**六条规则逐条判定并给出理由**，与冻结合同的六条一一对应：

| 规则 | 判定文本 | 结果 |
| --- | --- | --- |
| 风险分 | `Risk score 91 > 80: passed.` | 通过 |
| 置信度 | `Confidence 0.88 > 0.85: passed.` | 通过 |
| 敞口 | `Risk exposure 100% > 70%: passed.` | 通过 |
| 减仓上限 | `De-risk limit 30 percentage points > 0: passed.` | 通过 |
| RISK 白名单 | `A held risk asset with positive value is on the user-approved risk allowlist: passed.` | 通过 |
| DEFENSIVE 目标 | `A user-approved defensive target is available with no conflicting portfolio category: passed.` | 通过 |

批准结果：`action: SWAP_TO_SAFE`，`sourceAsset: ETH` → `targetAsset: USDC`，**`reduceExposurePct: 30`**。

复核要点：规则文本是**逐条渲染的判定过程**，不是事后拼的一句话结论。每条都带实际数值和阈值，可被第三方独立重算。

## 三、执行后独立读取与验证（实测）

执行回执（Mock adapter）：

```
sourceAmount: 3        （卖出 3 ETH）
targetAmount: 8100     （收到 8100 USDC）
```

独立重读的组合（`after` 是**新读取**，不是从回执推算出来的）：

| | 总资产 USD | 风险资产 USD | 防御资产 USD | 敞口 |
| --- | ---: | ---: | ---: | ---: |
| before | 30,000 | 30,000 | 0 | 100% |
| after | 27,000 | 18,900 | 8,100 | **70%** |

持仓变化：`ETH 10 → 7`、`USDC 0 → 8,100`。`after.timestamp`(`08:42:32.418Z`) 晚于 `execution.timestamp`(`08:42:32.417Z`)，读数没有倒退也没有早于执行。

**验证 8 项全部 PASSED**，逐项为：

1. 重读属于同一钱包
2. 重读证据未倒退、未早于执行
3. 兑换方向仍为 RISK → 用户批准的 DEFENSIVE
4. 源资产余额减少量与执行回执一致
5. 防御资产余额增加量与执行回执一致
6. **执行量与批准的百分点在市价下一致**
7. 资产身份与未获批资产余额未变
8. 风险敞口从 100% 降至 70%

### 第 6 项为什么是重点

`src/domain/verification.ts:14-17` 的核算方式带有一条关键注释：

> `// Price the pre-swap balances at the market quote so a market loss cannot expand the authorization.`

它**不用 `before` 组合里那份旧的美元估值**，而是用市价重新给交易前余额计价：

```
quotedTotalUsd = 10 ETH × 2700 = 27,000
executedExposurePoints = 3 × 2700 / 27000 × 100 = 30 ✓
```

这一点很重要：`before.totalUsd` 记的是 30,000（对应 ETH=3000 的旧价），而市价已跌到 2700。若直接按 30,000 的 30% 换算，允许卖出的数量会比授权时**更大**。用市价重算把这扇门关掉了——**市场下跌不能放大授权额度**。这是防越权，不只是数字比对。

## 四、重复事件拦截（实测）

在事件已占用的情况下连续发起 3 次人工执行请求：

```json

 "code":"EVENT_OCCUPIED",
 "detail":"This risk event already owns its execution opportunity; the server continues observations.",
```

拦截之后的实际状态：

- 事件总数 **仍为 1**（未产生第二个事件）
- 该事件卖出量 **仍为 3 ETH**（未发生第二次卖出）
- `activeEvent` 仍指向原事件，`halted: false`

即：**重复请求没有获得第二次执行机会，也没有被静默吞掉——它被明确拒绝并给出原因。**
