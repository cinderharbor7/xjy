## Abstract / 摘要

新增 `/investigate` 和 `POST /api/transaction-checks`。一次查询只读交易、回执、历史区块及固定池元数据，形成中文核验报告。保留 Guardian 保护流程；报告不构成交易批准。

## Background / 背景与动机

当前 B 解释的是固定池当前/前五分钟聚合卖压。该入口没有交易哈希参数，依赖 Portfolio/Market，不能核验一笔指定历史交易。研究案例中的大额转账也不足以证明卖出。

## Goals And Non-Goals / 目标与非目标

完成一次有出处、有范围的真实核验，帮助新手辨别已知事实。排除全链分类、路径追踪、身份判定、市场预测、LLM、交易建议与执行。

## Proposal / 设计方案

新增局部 Zod 报告合同、只读 Reader 和确定性解释 Service；HTTP 装配固定配置，前端只请求和展示。链上金额使用字符串。支持池内两种方向同时存在时明确说明双向，不推断净行为。

## Support Lens Checks / 专项设计检查

| Lens | 检查 | 结论 |
| --- | --- | --- |
| api-designer | 新增查询资源、错误语义和兼容性 | POST 返回临时报告，不创建持久资源；200/400/403/404/409/415/503，有 no-store 和 Problem JSON |
| architecture-designer | 外部读取与解释、交易权限边界 | 只读装配不导入 Guardian runtime 或执行器；模块可分别替换和测试 |

## Boundary Scenarios / 边界场景

非法哈希拒绝；未知交易返回 404；pending 返回 409；reverted 展示失败且没有成功兑换结论。RPC/错链/坏数据/重组返回安全错误。相同查询可重复，没有签名副作用。并发请求独立读取。无存储迁移、租户或钱包授权，沿用本机同源访问限制。

## Rationale / 理由与取舍

| 方案 | 取舍 |
| --- | --- |
| 在 RescueSession 中塞核验结果 | 无必要地要求钱包和风险评分，会混淆批准与查证 |
| 一次支持所有 DEX 和交易所 | 数据和解释范围超出当前能力 |
| 单独只读切片 | 边界清楚、可快速验证，覆盖范围必须始终展示 |

## Compatibility / 兼容性

纯新增路径和局部合同；旧公共 schema、路由、CLI、配置和 Guardian 状态保持。无需迁移或兼容层。去掉新增页面、接口和模块即可回退，不清除现有数据。

## Operational And Security Impact / 运行与安全影响

固定服务器 RPC，不接受用户提供 URL。保留超时、禁重试和 RPC 错误脱敏。没有缓存或降级。页面不暴露 RPC。历史池不存在或元数据不匹配时明确失败，不能补出假结论。

## Implementation And Transition / 实现与过渡

先固定局部合同，再独立实现读取/解释及页面，最后装配 API、完成真实案例和旧流程回归。首页仅加核验页导航。
