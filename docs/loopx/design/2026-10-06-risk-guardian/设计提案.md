# 保留工程边界，将核心合同切换为单向资产风险防护

Author(s): 项目架构负责人
Last updated: 2026-10-06
Status: Accepted
Discussion: 本聊天架构审计、ABCD讨论、开始授权与30个百分点裁决
Source requirements: .loopx/intake/2026-10-06-risk-guardian/requirements.md
Support lenses: architecture-designer, api-designer

## Abstract / 摘要

复用服务/Adapter/Policy/编排结构，替换借贷专属合同；新增Portfolio、Market，MVP只Mock SWAP_TO_SAFE。有效Aave读实现隔离到extensions/aave，保持外部读取行为，不重新搭建项目。

## Background / 背景与动机

旧Risk把无债务当零风险，HF贯穿合同、策略、执行和首页；无法表达无借款却100% ETH的组合。已有门控与重读结构可复用，避免重写工程。

## Goals And Non-Goals / 目标与非目标

目标是100%→70%的可审计Mock闭环及四人并行边界。排除真实DEX/钱包/LLM/交易、基础设施、重新入场和UI大改。

## Proposal / 设计方案

Portfolio和Market独立；Risk确定性，Agent无执行权；Policy使用用户预设资产名单和百分点上限；Executor只接结构化批准；重读后验证效果。USDC只表示Demo的user-approved defensive asset。

## Support Lens Checks / 专项设计检查

architecture-designer确认单仓库和模块职责；api-designer确认/API路径与新旧合同迁移、错误、配置/模式边界与OpenAPI。无需分页/认证账户、持久幂等或限流服务：此入口是本地单wallet Mock演示，每请求独立状态。

## Boundary Scenarios / 边界场景

空组合明确定义敞口0；非法/重复资产与名单交叉拒绝；门槛等号不触发；未批准/反向/未知资产/超限执行拒绝；Mock重复执行失败；并发请求各自独立；执行失败无after，重读失败明确报错；效果失败保留真实after并停止。无真实网络超时/补偿交易，扩展保留原错误处理。无数据库或持久数据迁移。

## Rationale / 理由与取舍

拒绝整仓重建，已有边界足够；拒绝只改UI名称，领域耦合仍存在；拒绝把Aave聚合债务假装成钱包Portfolio或其7200区块行情假装5m/1h；不提前启用REPAY_DEBT/WITHDRAW_PROTOCOL。

## Compatibility / 兼容性

/api/rescue保留URL但响应整体更换为新Session，只有仓库页面和测试消费者，用户明确要求替换，不加旧格式shim。/position和/api/position以及所有Aave读取字段/状态不变，原有效实现搬迁。新核心不依赖扩展，扩展不依赖新核心。

## Operational And Security Impact / 运行与安全影响

Mock无需key；可信PolicyConfig仅由服务器装配，不能由API/Agent提供。交易回执不是保护成功证明；验证来自重读。无实际写链权限、自动重试或回退。保留未提交内容，不commit/push/discard。

## Implementation And Transition / 实现与过渡

隔离Aave，冻结新合同，在原模块调整消费者和Mock状态，替换首页及文档，最后独立审查与fresh验证。完整设计以下同目录文件为准。

## Open Questions / 待决问题

无。比例口径已明确为百分点。

## Detailed Design Handoff / 详细设计交接

新Data/Behavior/Interface合同及权限方向必须保持；局部文件实现可自行选择，禁止扩需求。
