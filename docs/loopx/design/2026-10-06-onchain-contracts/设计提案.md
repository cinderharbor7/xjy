# 用两个独立数据合同固定 A→B 的链上信号交接

Author(s): 项目架构负责人
Last updated: 2026-10-06
Status: Accepted
Discussion: 用户两个合同的实施请求及四项口径答复
Source requirements: .loopx/intake/2026-10-06-onchain-contracts/requirements.md
Support lenses: architecture-designer

## Abstract / 摘要

新增两个Zod及infer合同，字段和统计含义固定；合同与旧Portfolio/Market/Investigation分离，暂不接运行流程。证据按type引用交易/区块/事件，避免BLOCK伪造txHash。

## Background / 背景与动机

现有Market仅价格，调查evidence是string[]；A与B没有统一资金行为输入。用户明确选择总卖出、前一个同长窗口、正基线、按txHash/tx.from去重及分类证据。

## Goals And Non-Goals / 目标与非目标

目标是可验证且可交接的数据结构；非目标是真实DEX读取、风险算法、Agent接入、监控、签名、写链、基础设施或改HTTP响应。

## Proposal / 设计方案

OnchainSignalState为ETH/DEX_SELL_PRESSURE快照，金额和ratio有限，窗口UTC半开；OnchainEvidence为严格三分支。仅新增独立导出，旧API和权限不变。

## Support Lens Checks / 专项设计检查

architecture-designer确认生产/消费责任固定在A/B，数据合同不授予执行权限，不增加服务部署或数据库。

## Boundary Scenarios / 边界场景

拒绝零基线、非有限/不一致ratio、非法时间/计数、缺引用、未知字段；无当前交易允许零量/零计数快照。证据可抽样/包含前窗口引用，格式通过不证明内容真实。无外部调用或副作用，重试/超时/并发/迁移补偿不适用；旧流程回归由现有测试检查。

## Rationale / 理由与取舍

拒绝把链上信号混入Market/Portfolio，拒绝把旧调查string[]偷偷换成对象数组；用户已选择前一窗口而非均值、正基线而非nullable比值。新增合同成本小，但仍需未来Adapter实际填充。

## Compatibility / 兼容性

纯新增导出，没有旧调用方需迁移；旧DTO/HTTP/Mock原样保留。回滚只涉及本次新增合同与说明，不涉及持久数据。

## Operational And Security Impact / 运行与安全影响

source只用公开标签/URL，不含RPC密钥；输入不携带钱包权限。Schema检验结构，不能证明交易确实卖ETH或区块canonical；A/B仍负责真实证据核验。

## Implementation And Transition / 实现与过渡

合同和回归测试落地，再更新README/合同说明与AB交接；独立审查固定字段和统计边界。冻结实施阶段无新commit/push授权；2026-10-07用户明确授权发布，记录见来源clarification，不改变数据设计。

## Open Questions / 待决问题

本次范围内无；真实采集配置、触发阈值、持续监控另属后续开发。
