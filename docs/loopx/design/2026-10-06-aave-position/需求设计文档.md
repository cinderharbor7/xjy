## 四、详细设计

### 4.1 Position 与查询详细设计

#### 4.1.1 需求内容

读取有效 Ethereum 地址的借款仓位，向 B 提供 PositionState，向 D 提供含行情及证据的 PositionSnapshot。

#### 4.1.2 方案设计与合同

**Data Contract D-001 / AC-002,004,005**：原八个 schema 不变；新增 PositionSnapshot discriminated union。ACTIVE 包含原 PositionState、marketChanges、evidence；NO_DEBT 包含 position=null、message、evidence，没有假 HF 或行情填充值。两种结果均有 mode=LIVE、wallet。证据保留 chainId/network/provider/pool/oracle/ETHasset 地址、blockNumber/hash/timestamp 和可选 txHash；本轮 eth_call 不填 txHash。

**Behavior Contract D-002 / AC-003,004,006**：账户、USD 基准单位、当前价格与 timestamp 绑定同一个已获取区块。HF 1e18，base currency 必须是 USD zero address，unit 必须是十的正整数次幂；拒绝异常值。有债务才创建 PositionState；没有债务则明确结果。历史价格在当前区块减 7200 的真实区块读取该时点的 Oracle/单位，以 `(current / previous - 1) * 100` 计算百分比，并返回参考区块、hash、时间与实际间隔。

**Interface Contract D-003 / AC-002,007**：Adapter.getPosition(wallet):Promise<PositionState> 不变；getSnapshot(wallet):Promise<PositionSnapshot> 为新只读接口。NO_DEBT 的 getPosition 明确抛出可识别错误。API 输入严格 `{wallet:string}`，有效 EVM 地址，ACTIVE 与 NO_DEBT 均 HTTP 200；非法输入 400，配置错误 503，链读取失败 502；响应 no-store 和 X-Position-Mode: LIVE。

**Operational Contract D-004 / AC-008,009**：ETHEREUM_RPC_URL 必填，AAVE_NETWORK 支持 ethereum-mainnet；viem transport retryCount=0、固定超时；没有备用 RPC、Mock fallback、钱包 account 或私钥。独立新增 /position 页面，只调用查询接口；首页增加入口但原 Run Demo 行为不变。

#### 4.1.3 核心读取流程

验证地址、链和区块；从地址 Provider 定位 Pool/Oracle；读取账户与币价；按债务返回 ACTIVE 或 NO_DEBT；验证整个 snapshot。ACTIVE 再附上历史窗口；所有异常直接报错。

#### 4.1.4 边界条件

无地址/非法输入被拒绝；空仓位、仅抵押无借款为 NO_DEBT。错链、缺配置、零单位、非 USD 基准、零价格、异常 HF、历史区块不足或 RPC 失败均终止。重复/并发是无状态读，无写链权限；无需幂等持久化。无数据库迁移、旧数据覆盖、补偿或降级；既有 Mock 与实时查询独立。

#### 4.1.5 不变行为

PositionState 和八个旧 schema、Mock rescue、Policy 权限与 Executor 输入、旧 API 返回值保持不变；由原测试、新增 API 测试和独立 diff 审查验证。

## 六、其他组件设计

ETHEREUM_RPC_URL 服务端配置需支持窗口内历史 eth_call 和 EIP-1898 blockHash + requireCanonical。当前和历史合约读取分别绑定证据 hash；非 canonical 或不支持的读取直接失败。AAVE_NETWORK=ethereum-mainnet。MOCK_MODE 仍只控制 rescue，不把真实查询标为 Mock。本地验收可使用公开 dRPC；端点不通过客户端或异常响应泄漏。

## 七、接口设计

POST /api/position 为只读入口；schema 在 domain/schemas/position-read.ts，类型从同名 types 文件 infer。API 不导入 Risk/Investigation/Policy/Execution/Rescue；请求不能覆盖 RPC/合约配置。实际数据沿 camelCase 给 B/D 复用。

## Planning Handoff

plan2exec 可决定文件分配、测试实现和常规 UI 展示；不得改旧契约、无借款语义、链/市场范围、只读权限或价格窗口含义。若需改变这些边界应重新确认。实现前建立一个计划，分别验证契约、Adapter、UI、集成与最终现场验收。
