# 用可替换的只读 Adapter 交付 A 的 Ethereum 数据

Author(s): A / 架构负责人
Last updated: 2026-10-07
Status: Accepted
Discussion: 用户开始A任务，并明确批准三项数据范围/口径
Source requirements: .loopx/intake/2026-10-07-ethereum-live-data/requirements.md
Support lenses: architecture-designer, cli-developer

## Abstract / 摘要

新增Ethereum组合、Chainlink行情及Uniswap单池卖压Adapter。B/D收到既有合同；CLI独立读取，Mock Rescue不变。共用仅包含读取方法的viem client，按canonical block hash取状态，失败明确停止。

## Background / 背景与动机

主Guardian外部能力仍为Mock；现有Adapter接口与冻结Onchain合同可承接真实实现，Aave聚合仓位不能替代钱包资产或5m卖压。

## Goals And Non-Goals / 目标与非目标

目标为ETH/USDC组合、真实oracle行情和单池卖压JSON及证据。此次不处理其他钱包资产、全市场成交、B/C算法、页面、监控、LLM、交易或数据库。

## Proposal / 设计方案

新增modules/onchain作为A的共享Ethereum读取与Signal边界，portfolio/market各实现现有接口。共用快照/价格工具是RPC基础能力，不是跨业务调用。CLI支持human默认与--json，只查询指定部分或完整数据，D后续装配。

## Support Lens Checks / 专项设计检查

architecture-designer检查只读权限、快照一致性、失败与Mock隔离；cli-developer检查help、JSON/stderr、明确范围和无交互运行。不增加服务拓扑。

## Boundary Scenarios / 边界场景

空钱包合法；报价必须正且不过期；零基线不能生成Signal。严格解码全部日志，重复相同日志去重、冲突拒绝，使用实际区块时间。部分RPC失败、超时或重组都失败，不提供补值/重试。无写操作，因此没有执行竞争/补偿状态；请求仅有局部缓存和受限并发。旧Mock/API/Aave不变。

## Rationale / 理由与取舍

保留已有viem，避免另写RPC协议栈。采用用户批准单池/Chainlink，拒绝全市场扫描、固定USDC=$1、固定块数充当时间窗口。历史oracle点可能同轮次，必须说明其采样含义；事件区块价格读取增加RPC成本。

## Compatibility / 兼容性

纯新增Adapter、Onchain service及内部验收CLI；getPortfolio/getMarketState/冻结合同原样保留。CLI的state/evidence外壳用于验收，核心业务仍只消费Domain合同。原MOCK_MODE不用于开启真实交易。移除新增只读入口即可撤回，不涉及持久数据。

## Operational And Security Impact / 运行与安全影响

仅服务端ETHEREUM_RPC_URL；PublicClient无钱包/写方法，retryCount=0、有限超时。错误及source不含RPC URL/密钥。固定主网地址与池身份验证。真实只读查询可能受provider历史读取/日志额度限制，失败清楚报告。

## Implementation And Transition / 实现与过渡

共享读取能力经测试验证后，三个Adapter独立落地；验收入口组合Domain数据及Evidence，再由B/D逐步接入，原Mock可继续运行。

## Open Questions / 待决问题

本次范围内无。用户已选择原生ETH/USDC、单池5m与波动代理；监控及实际交易后续处理。

## Detailed Design Handoff / 详细设计交接

详细设计保持三个用户裁决与既有合同，固定A/B/D接口、canonical引用、严格失败及CLI输出边界；不重新解释统计或侵入其他开发区域。
