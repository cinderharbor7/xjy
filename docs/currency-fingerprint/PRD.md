## 1. 产品定义

货币指纹将一个加密货币币种的行情、交易活动和市场环境，转换为具有颜色、形态与动态节奏的数字图形。用户先通过图形发现币种，再查看支撑图形的数据，最后将某个时刻的指纹快照收藏为 NFT。

产品的核心体验是“观察 → 理解 → 收藏”：观察不同币种在同一套规则下呈现的视觉差异，理解差异对应的数据，再保留一份可追溯的链上作品。

NFT 表示对指纹作品的所有权，不表示持有对应的 BTC、ETH 等资产，也不发行新的同质化货币。指纹不是信用评级、价格预测或交易信号。

### 1.1 首版目标

- 用户打开首页即可看到一个重点币种的大幅动态图形，并进行轻度鼠标交互。
- 用户可以从两列币种列表进入详情，看到图形、基础信息与传统数据之间的对应关系。
- 每个数值和图形参数都能解释其来源、时间与缺失状态。
- 用户可以在 BOT Chain 测试网，将当前指纹快照铸造成可收藏、可转让的 NFT。
- 前端保持简单，方便后续按用户反馈调整布局和视觉。

### 1.2 首版不包含

交易、兑换、托管资产、自动投资、收益推荐、信用评分、NFT 二级交易市场、跨链铸造、主网发行、用户账号系统和全链资产索引。

真实社交媒体观点冲突网络属于后续范围。现有新闻来源关联不能替代观点关系分析。

## 2. 用户与使用场景

以下用户划分是本版设计假设，尚未通过用户研究验证。

| 用户 | 主要任务 | 产品提供的价值 |
| --- | --- | --- |
| 加密市场观察者 | 快速浏览币种差异，进一步查看数据 | 用图形建立第一印象，用指标确认含义 |
| 数字艺术收藏者 | 选择一个有意义的时刻，保存作品 | 将市场快照转换成有来源标记的 NFT |
| 项目展示与体验用户 | 在短时间内理解数据可视化与链上收藏 | 无钱包也能浏览，收藏时才进入钱包流程 |

典型场景：用户在首页看到 ETH 的动态指纹，进入详情了解其振幅与成交活动；确认收藏后，预览固定版本、连接钱包、支付测试 BOT Gas，最终获得 NFT 和链上交易链接。

## 4. 信息架构与用户旅程

```text
探索图鉴
├─ 焦点币种与动态图形
├─ 搜索 / 类别筛选 / 排序
└─ 币种详情
   ├─ 名称、简介、基础行情
   ├─ 纹理指纹 / 流体形态
   ├─ 行情曲线、数据切片、市场情绪、新闻、来源状态
   └─ 收藏快照
      ├─ 下载元数据
      └─ 连接钱包 → 核对网络 → 确认铸造 → 链上确认

我的收藏
├─ 本浏览器收藏记录
└─ NFT 与交易详情链接

读懂指纹
└─ 数据映射、缺失值规则、收藏版本说明
```

| 阶段 | 用户操作 | 页面反馈 | 完成条件 |
| --- | --- | --- | --- |
| 发现 | 打开首页，移动鼠标查看焦点图形 | 图形轻度响应，显示币种、精选标记与数据状态 | 不连接钱包即可理解展示对象 |
| 浏览 | 搜索、筛选或排序 | 列表与结果数量更新，空结果有恢复入口 | 找到目标币种 |
| 理解 | 打开币种详情，切换区间或图形模式 | 图形、曲线与指标有明确口径 | 知道图形表达什么及数据来自哪里 |
| 定格 | 点击收藏 | 冻结当前数据，展示待铸造的固定图像与来源状态 | 刷新行情不改变已打开的收藏快照 |
| 授权 | 连接钱包、切换网络、确认 Gas | 按阶段说明钱包操作与链上状态 | 用户在钱包中确认交易 |
| 保存 | 等待回执 | 显示交易链接，核验后生成收藏记录 | 链上所有者、Token ID、元数据摘要可核对 |
| 回看 | 打开我的收藏 | 展示本浏览器记录并提供链上链接 | 不把本地记录误称为当前全部链上资产 |

## 5. 功能需求

优先级：**P0** 为首版核心闭环；**P1** 为数据与体验完善；**P2** 为探索方向。优先级表达目标范围，不表示已经完成。

### 5.1 首页与币种图鉴

| 编号 | 优先级 | 需求与规则 | 验收条件 |
| --- | --- | --- | --- |
| H-01 | P0 | 展示一个重点币种的大幅动态图形、名称、简短说明、价格、24h 涨跌和详情入口 | 首屏明确币种身份、数据状态与下一步操作 |
| H-02 | P0 | 焦点图形支持轻度鼠标视角变化和暂停；不依赖复杂拖拽 | 鼠标移开后回归默认视角；暂停按钮状态明确 |

### 5.3 收藏与 NFT

| 编号 | 优先级 | 需求与规则 | 验收条件 |
| --- | --- | --- | --- |
| N-01 | P0 | 点击收藏即冻结快照，展示实际待铸造 SVG、币种、时间、数据模式、网络与存储方式 | 下载与铸造使用同一份元数据，预览不随行情刷新 |
| N-02 | P0 | 支持下载包含图像与快照的 JSON | 无钱包也能下载；文件可解析并恢复 SVG |
| N-03 | P0 | 通过浏览器 EVM 钱包连接账户 | 不读取私钥；拒绝授权、无钱包有清楚反馈 |
| N-04 | P0 | 铸造前核验 BOT 网络和目标合约 | 错误网络不能直接发送；未知或不匹配的合约不能继续 |
| N-05 | P0 | 用户核对钱包费用后主动确认铸造 | 不自动提交交易；合约不收额外铸造费，Gas 由测试 BOT 支付 |
| N-06 | P0 | 显示等待签名、已广播、等待确认、已确认和失败状态 | 广播交易后即可查看哈希；不能把哈希返回当作铸造成功 |
| N-07 | P0 | 成功回执后读取所有权和元数据摘要 | 验证通过才标记成功；读取失败标记“已提交/待核验”，不能诱导立即重铸 |
| N-08 | P0 | 演示快照在预览和元数据中明确标记，并额外确认 | 不将演示 NFT 描述为真实市场记录 |
| N-09 | P0 | 保留元数据版本和不可变快照 | 铸造后没有修改同一 Token 元数据的产品入口 |
| N-10 | P0 | 防止同一账户重复铸造完全相同的元数据 | 合约拒绝重复；仅关闭并重开预览产生新时间，不应宣传成新的市场事件 |
| N-11 | P1 | 保存待确认交易并在重开页面后恢复核验 | 不丢失交易哈希，避免重复付费；当前尚未实现 |

NFT 是数据驱动的艺术表达。元数据由收藏者提交，链上记录不证明来源数据真实，也不构成可信价格预言机。

### 5.4 我的收藏

首版展示当前钱包在当前浏览器中完成核验的收藏记录，内容包括图像、币种、Token ID、合约、采集时间、数据模式和交易链接。

无钱包时提供连接入口；没有记录时提供返回图鉴入口。钱包切换后更新对应记录，不展示为同一账户资产。

首版文案使用“收藏记录”。由于记录可能在铸造后被转让，页面不得将历史记录默认描述为“当前拥有”；最终所有权以链上查询为准。跨设备恢复、全链索引与动态所有权刷新为 P1。

### 5.5 指纹说明与设置

“读懂指纹”解释输入数据、归一化、视觉含义、缺失值与 NFT 固定版本。说明应位于首页和详情均可找到的位置。

测试网合约部署与地址配置属于首版开发/演示配置入口。正常收藏流程不应要求每个用户部署自己的合约；公开演示前应配置经核验的项目合约。现有可部署入口保留用于调试，是否在对外页面隐藏为发布决策项。

## 6. 指纹生成规则

### 6.1 首版映射

| 视觉变量 | 输入 | 首版处理 | 用户应如何理解 |
| --- | --- | --- | --- |
| 基础色相与结构种子 | 稳定的币种身份 | 固定映射，不随价格刷新改变 | 区分币种；不是涨跌或风险分数 |
| 色彩分布 | 市场恐惧贪婪指数 0–100 | 归一化至 0–1；缺失使用中性值 | 描述全市场背景，多个币种共享这一背景 |
| 表面起伏 | 24h 日内振幅 | `(最高价 − 最低价) / 开盘价 × 100%`，映射上限为 15%，保留最小可见起伏 | 振幅越大，形态越不平整；超过上限仍显示原始数值 |
| 动态节奏 | 24h USDT 成交额 | `log10(max(成交额,1))/12` 后限制到视觉范围 | 表示绝对交易活动，不等同于按市值调整后的活跃度 |
| 指纹固定版本 | 币种种子、映射参数、渲染版本 | 固定时间和视角，生成 SVG | 收藏某一快照，而非永久更新的行情图形 |

日内振幅与统计波动率是不同指标。首版使用振幅驱动形态；详情中的统计波动率单独展示，不能互换标签。

### 6.2 一致性与降级

同一币种、参数和渲染版本应生成相同的固定图像。NFT 可以使用较低复杂度的矢量纹理，但必须在确认前展示最终图像，不能将其称为流体画面的逐帧复制。

缺失输入使用中性视觉参数，数值仍显示 `—`，并提示形态存在默认参数。中性形态不代表市场平稳、安全或低风险。

WebGL 不可用时回退到纹理视图；低性能设备降低分辨率、线条数或帧率。用户暂停、后台标签页和系统“减少动态效果”设置均应被尊重。恢复可见性时不能出现空白图形。

## 7. 数据需求

### 7.1 身份、单位与时间

每个币种需有稳定内部 ID、名称、缩写和网络。DEX 资产必须通过网络与合约地址识别，不能只按名称匹配；原生资产与包装币必须区分。公开开发仓库显式维护映射，不通过同名搜索自动认定官方仓库。

数值至少记录来源、单位、适用对象和状态。区分来源数据时间、抓取时间与用户收藏时间；抓取成功不代表底层数据刚刚更新。链上元数据中的价格必须携带报价资产口径，不能把 USDT 无条件解释成 USD。

### 7.2 来源与字段范围

以下为产品字段需求，非承诺所有来源对所有币种均可返回。频率是本项目缓存/采集方案，不是第三方服务额度保证。

| 数据域 | 首版重点字段 | 后续字段 | 来源与边界 |
| --- | --- | --- | --- |
| 价格 | 现价、高低价、24h 涨跌、小时 K 线 | 1h / 6h 收益率 | Binance；DEX 价格按具体池口径展示 |
| 成交 | 24h 报价资产成交额、成交笔数 | 1h / 6h 成交量 | 不混淆基础资产数量与报价资产金额 |
| DEX 行为 | 买入/卖出笔数 | 买卖比例、多时窗对比 | DEX Screener；仅针对返回交易池 |
| DEX 流动性 | 返回池数量、流动性、最大池流动性 | 池龄、FDV、市值 | 包装币单独标记；不能声称全市场覆盖 |
| 盘口与压力 | 最优买卖价、价差、±1% 深度、主动买入占比 | ±0.5% 深度、盘口不平衡、主动卖出量 | Binance；说明档位截断和时间窗口 |
| 波动 | 日化波动率、区间最大回撤 | 收益率 Z-score、更多区间 | 从原始 K 线计算并记录公式版本 |
| DeFi 基本面 | 所属链 TVL | 协议 TVL、TVL 1d / 7d 变化、部署链数 | DefiLlama；链级与协议级指标分开 |
| 新闻热度 | 文章、来源、时间 | 1h / 24h / 7d 提及量、独立媒体数 | GDELT；限量文章列表不等于总新闻数量 |
| 新闻评价 | 首版不生成币种独立情绪值 | 正负面比例、事件类别、重要性 | 需另行建设文本分析与质量评估 |
| 开发活动 | Stars、Forks、Issues、最后推送 | Commits 7d / 30d、贡献者、最后提交 | GitHub；最后推送不等于最后提交 |
| 市场背景 | 恐惧贪婪指数及其日期 | 历史指数对比 | Alternative.me；按要求标明来源 |

波动率计算采用已收盘小时收盘价的对数收益率标准差，再乘 `sqrt(24)`，以百分数表示。7d 视窗是在七天样本上估计日化波动率；不是七天累计波动率。最大回撤基于所选窗口内的小时收盘价。

### 7.3 更新与状态

行情、K 线和 DEX 默认缓存 60 秒；盘口 30 秒；新闻 15 分钟；TVL 30 分钟；市场情绪 1 小时；GitHub 6 小时。首版由页面访问或手动刷新触发读取，并非后台定时采集。后续如增加自动刷新，需单独控制并发与来源频率。

| 状态 | 界面行为 | 收藏行为 |
| --- | --- | --- |
| 演示 | 持续显示演示标记；不冒充历史行情 | 允许，需额外确认且写入元数据 |
| 公开快照 | 显示来源及时间，不承诺持续实时 | 允许，将各来源时间一并冻结 |
| 过期缓存 | 明确旧数据仍在显示及失败原因 | 可收藏，但需提示过期并记录状态；属于目标规则 |
| 不可用 | 数字显示 `—`，关联图形用中性参数 | 关键行情缺失时禁止铸造；可继续浏览其他数据 |
| 不适用 | 显示不适用及原因 | 不作为来源故障或资产风险结论 |

来源之间可以部分成功，不能因新闻超时隐藏已经取得的行情。不得在公开模式中静默混入演示值；用户切回演示应是明确操作。

## 8. 上链与快照规范

### 8.1 网络

| 参数 | 值 |
| --- | --- |
| 网络 | Bohr Testnet / BOT Chain Testnet |
| Chain ID | `968` |
| Chain ID Hex | `0x3c8` |
| RPC | `https://rpc.bohr.life` |
| Gas Token | 测试 BOT |
| 区块浏览器 | `https://scan.bohr.life` |

### 8.2 元数据内容

| 内容 | 要求 |
| --- | --- |
| 标识 | 名称、币种内部 ID、缩写、资产网络及必要的合约身份 |
| 时间 | 收藏时间、行情数据时间、情绪指标时间、必要的抓取时间 |
| 数据 | 价格及报价单位、24h 涨跌、成交额及单位、振幅、情绪指数 |
| 来源 | 数据提供方、作用范围、演示/公开/过期/缺失状态 |
| 图形 | 固定 SVG、归一化后的映射参数、确定性种子 |
| 版本 | 快照结构版本、映射规则版本、渲染版本 |
| 核验 | 对实际提交的元数据 URI 计算摘要，保存并支持链上读取 |

当前合约方案为 ERC-721，SVG 嵌入 JSON，JSON 作为 data URI 保存；当前 URI 上限为 18,000 字节。超出上限时在钱包调用前提示，不能发送明知会失败的交易。

完整上链会产生较高存储 Gas。确认页应清楚说明费用由钱包估算，不把本地测得的 Gas 数量当作固定费用。是否改用外部内容寻址存储是后续方案选择，未经确认不改变当前完整上链语义。

### 8.3 交易异常

| 异常 | 必须提供的反馈 |
| --- | --- |
| 未安装钱包 / 未授权 | 解释缺少条件，保留预览和下载能力 |
| 网络不匹配 | 请求添加或切换 BOT 网络；用户拒绝后停止 |
| 合约未配置 / 代码不匹配 | 停止铸造，不将交易发送到任意地址 |
| Gas 余额不足 | 明确需要测试 BOT，保留快照 |
| 用户取消 | 显示已取消，不生成成功记录 |
| 已广播但未确认 | 展示交易哈希，继续核验，不直接显示失败或成功 |
| 交易回滚 | 显示失败及可读原因，保留链上链接 |
| 回执成功但核验读取失败 | 显示已确认、核验待完成；提示查看链上记录 |
| 本地存储失败 | 保留真实链上成功状态，提示保存 Token ID 和交易链接 |

## 9. 视觉与交互要求

采用瑞士国际主义风格：规则网格、左对齐、鲜明的字体层级、有限色彩和克制装饰。图形承担主要视觉变化，界面帮助阅读和比较。

| 项目 | 要求 |
| --- | --- |
| 界面配色 | 白 `#fafaf8`、浅灰 `#f2f2ee`、黑 `#171717`；红 `#d72e24` 仅作操作与重点强调 |
| 数据配色 | 保留指纹颜色；涨跌同时提供正负号与数值，不只靠颜色识别 |
| 字体 | Helvetica Neue / Arial；中文使用系统无衬线回退；数字等宽对齐 |
| 层级 | 币种主标题、模块标题、数据值、来源说明形成清楚的四级阅读顺序 |
| 结构 | 直角容器、规则分隔线；不依赖阴影、渐变背景或装饰点阵建立层级 |
| 桌面 | 首页两列币种行，详情左信息右图形；核心内容保持对齐 |
| 移动端 | 列表与详情纵向排列；重要操作可点击，表格与数值不溢出 |
| 键盘 | 链接、按钮、筛选、弹窗可操作，焦点可见；弹窗关闭后有合理焦点位置 |
| 动效 | 支持暂停和减少动态效果；不将读取数据变成全页持续动画 |

视觉检查由用户完成。开发方交付后提供预览，根据用户反馈调整；不得把代码通过构建描述为视觉验收通过。

## 10. 技术与非功能要求

前端使用 HTML、CSS、原生 JavaScript 和 Tailwind。Vite 仅负责开发与构建；同源 Node 服务封装数据源、超时与缓存，避免浏览器直接承担所有来源的兼容性处理。首版不引入数据库或前端组件框架。

| 编号 | 优先级 | 要求 | 验证方式 |
| --- | --- | --- | --- |
| Q-01 | P0 | 公开数据请求有超时、缓存、失败状态和重复请求控制 | 模拟超时、失败、连续刷新，核验返回状态与请求量 |
| Q-02 | P0 | 初始浏览不依赖钱包、远程字体或 Shader Park 下载完成 | 检查依赖加载与降级路径 |
| Q-03 | P0 | 动画暂停/离屏/后台处理不破坏图形恢复；不能阻塞常用交互 | 功能验证；实际观感由用户验收 |
| Q-04 | P0 | 外部新闻与仓库内容安全作为文本展示，链接限制为允许的协议 | 检查数据到页面的处理路径 |
| Q-05 | P0 | 不记录私钥，不要求与铸造无关的资产授权 | 检查钱包调用与合约接口 |
| Q-06 | P0 | 合约与数据计算有可复现验证，交易提交和确认严格区分 | 自动化测试、公开测试网端到端验证 |
| Q-07 | P1 | 独立来源按完成先后更新，新闻读取不拖延行情展示 | 模拟慢新闻源，测量行情可用时间 |
| Q-08 | P1 | 目标设备上的帧率、首屏加载和内存占用有记录 | 先确定设备与网络基线，再制定数值门槛 |

首版不虚设未经测量的性能达标结论。低性能设备以静态或低频图形保证内容可读。

## 11. 发布验收与阶段安排

### 11.1 P0 验收清单

- 首页焦点、两列图鉴、搜索筛选和详情跳转按币种正确工作。
- 详情的行情、图形和收藏预览保持币种与数据模式一致。
- 公开数据失败、缺失与过期状态可辨认，不出现静默演示回填。
- 图形映射可解释，同一参数的固定 SVG 可以复现。
- NFT 下载与实际铸造内容一致，关键身份、报价单位、来源和时间可读取。
- 钱包拒绝、错误网络、错误合约、余额不足、回滚和待确认均有对应状态。
- BOT 测试网实际完成一次部署及铸造，核验 Token URI、摘要、所有权与交易链接。
- 演示数据 NFT 有明确标记，不与真实快照混淆。
- 用户完成桌面与移动端视觉验收，确认字体、色彩、层级和留白。

### 11.2 阶段安排

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| A. 展示闭环 | 首页、详情、图形、说明、下载 | 可独立演示，数据语义一致，用户完成视觉反馈 |
| B. 数据闭环 | 公开行情、来源状态、缓存、异常处理 | 成功与失败路径可核验，核心数据不被补充来源阻塞 |
| C. 链上闭环 | 项目合约、钱包铸造、确认与收藏记录 | 公开 BOT 测试网端到端验证完成 |
| D. 扩展 | 历史指标、交易恢复、全链收藏、新闻分析 | 每项单独定义来源与验收，再进入开发 |

不在本 PRD 中承诺未经确认的日程和人员配置。

### 11.3 体验评估

首轮使用小规模任务验证：用户能否找到目标币种，能否解释图形中的至少两个维度，能否识别演示与公开快照，以及能否在测试网完成收藏。先记录基线，再决定是否需要正式埋点和转化率目标；首版不引入额外第三方追踪服务。
