# Ethereum 交易核验 MVP

来源：用户确认面向链上交易新手的只读核验方向，并要求“拉一个分支，做一个 MVP 出来”。沿用现有 Ethereum 主网与 Uniswap V3 WETH/USDC 0.05% 单池边界。

## 目标与范围

输入一笔交易哈希，读取真实 Ethereum 交易、回执和区块，向新手说明转账事实与所支持池内的兑换证据。新增独立页面及查询接口，保留已有 Guardian 流程和公共合同。

不识别地址真实身份，不追踪后续路径或交易所成交，不查询内部调用，不预测价格，不作交易建议，不签名或调用 Policy/Executor，不接 LLM，不增加持久化、后台任务或依赖。

## Acceptance Criteria

- AC-001：`/investigate` 输入交易哈希，经独立 HTTP 接口查询；页面明确显示 Ethereum 主网、真实只读与覆盖范围。
- AC-002：返回外层交易的 from/to、原生 ETH 金额、input、状态、区块/hash/time 和回执日志数；金额使用精确十进制字符串。
- AC-003：仅以地址和元数据均匹配的固定池 Swap 日志识别 WETH→USDC、USDC→WETH 或两种方向均存在；USDC 数量不冒称美元价值。
- AC-004：普通转账或未发现支持范围内兑换证据时，不能宣称“没有出售”；即使出现卖出事件，也不推断交易者身份、动机、全笔净卖出或价格因果。
- AC-005：中文结论、确认事实、不能确认的部分、下一步查证和可点击来源完整展示；不生成风险分数或虚构置信度。
- AC-006：非法输入、找不到交易、未确认、错链、RPC/区块/日志异常均明确反馈；不回退 Mock、旧数据，不暴露 RPC 或密钥。
- AC-007：查询不依赖钱包/Portfolio，不接 Guardian runtime、Policy、Execution；旧接口、数据库及监控行为保持不变。
- AC-008：现有检查与新增契约、读取、判断和 API 测试通过；真实转账和真实支持池兑换完成 HTTP 与浏览器验收。

## Acceptance Scenarios

- TC-001 → AC-001/002/004/005：真实 20,059.2 ETH 转账显示金额、证据与“未证实卖出”，不写全链未卖出。
- TC-002 → AC-003/004/005：支持池 WETH→USDC 日志显示卖出证据及精确代币数量。
- TC-003 → AC-003/004：支持池反向及双向日志分别解释为买入、含双向兑换；不误判净卖出。
- TC-004 → AC-004/006：未支持协议的日志不被当作本池交易；伪造地址、错误池元数据或坏编码不能产生获信任结论。
- TC-005 → AC-006：非法哈希、未知哈希、pending、失败回执、错链、RPC 失败、重组与不一致回执有明确结果或错误。
- TC-006 → AC-007/008：重复查询没有交易副作用；Guardian 全套回归保持通过。

## 边界

本次新增局部查询合同，不修改冻结的 OnchainSignalState、RiskAnalysis、PolicyDecision 或 ExecutionResult。用户仅授权创建分支和实施，未要求提交、push 或 merge。
